## 第 1 阶段：工具层（热身，理解"轮子"怎么造）

### 1.1 `util/Logger.h` — 极简日志
- **功能**：线程安全、支持格式化、编译期可关。
- **关键语法**：单例（`static` 局部变量，C++11 起线程安全）、变参模板、`if constexpr`、宏 `__VA_ARGS__`、`thread_local`。
- **读什么**：`Log(...)` 模板函数、`LOG_INFO` 宏展开。
- **面试点**：
  - 为什么用 `static Logger inst; return inst;` 而不是 `new`？（线程安全单例，C++11 保证）
  - 日志为什么加 `std::mutex`？（多线程并发写 stdout 会交错）
  - `snprintf` 与 `fmt` 的区别？

### 1.2 `util/ThreadPool.h/.cpp` — 有锁线程池
- **功能**：固定线程数，`Submit` 返回 `future`。
- **关键语法**：`std::function`、`packaged_task`、`future`、`std::bind`、`condition_variable`、`unique_lock`。
- **读什么**：`Submit` 模板、worker 循环 `cv_.wait(lk, pred)`。
- **面试点**：
  - worker 为什么用 `cv_.wait(lk, [this]{ return stop_ || !tasks_.empty(); })`？（防虚假唤醒 + 停止条件）
  - `packaged_task` 与 `function` 的区别？（前者携带 future）
  - 析构时为什么要 `notify_all` + `join`？（唤醒所有 worker 让它们退出）

### 1.3 `util/MpscQueue.h` — 无锁队列 ⭐
- **功能**：多生产者/单消费者、有界环形队列，无锁。
- **关键语法**：`std::atomic<size_t>`、`compare_exchange_weak`、内存序（`relaxed`/`acquire`/`release`）、`std::optional`。
- **读什么**：`Push`（CAS 抢 head）、`Pop`（单消费者只动 tail）。
- **面试点**（**高频**）：
  - 为什么是 MPSC 而不是 MPMC？（多消费者改同一个 `tail_` 需要额外同步；MPSC 用"每消费者一个队列"绕开）
  - `memory_order_release` 写在数据、`acquire` 读数据，为什么？（保证数据写入对消费者可见）
  - `head_ - tail_ >= cap_` 判断队满，为什么用无符号回绕？（自然处理序号溢出）

### 1.4 `util/MpscThreadPool.h/.cpp` — 无锁任务池 ⭐
- **功能**：每个 worker 一个 `MpscQueue`，提交时轮询分发。
- **关键语法**：`MpscQueue<Task*>`（存指针，因队列元素需可平凡拷贝）、`thread_local`… 不，是每 worker 的 `mutex+cv`（仅用于睡眠唤醒）。
- **读什么**：`Submit`（轮询 + new Task）、`Run`（先无锁 Pop，失败才 wait）。
- **面试点**：
  - 为什么队列元素用 `Task*` 而不是 `std::function`？（`std::atomic<T>` 要求 T 可平凡拷贝）
  - 无锁队列为什么还要 `mutex+cv`？（只为"空时睡眠/有任务时唤醒"，任务存取本身无锁；`pending` 标志防丢失唤醒）
  - `Submit` 返回 `false` 时怎么办？（队列满，调用方回退同步处理，不丢请求）

## 第 2 阶段：网络层（Reactor 核心）

### 2.1 `net/Buffer.h` — 读写缓冲
- **关键语法**：`std::vector<char>`、`std::string_view`、`memcpy`/`memmove`。
- **面试点**：`Peek()` 返回 `string_view` 为什么不拷贝？（零拷贝查看）；`Compact()` 为什么要 `memmove`？

### 2.2 `net/EpollPoller` — epoll 封装
- **关键语法**：RAII（构造 `epoll_create1`、析构 `close`）、`epoll_ctl`/`epoll_wait`。
- **面试点**：ET 和 LT 的区别？为什么 ET 必须循环读到 `EAGAIN`？

### 2.3 `net/Channel.h` — fd 事件封装
- **关键语法**：`std::function` 回调、位运算（`events_ |= EPOLLIN`）。
- **面试点**：为什么把 fd 的事件和回调封装成 `Channel`？（解耦"事件源"和"处理逻辑"）

### 2.4 `net/EventLoop` — 事件循环 ⭐
- **关键语法**：`eventfd`、`std::atomic<bool> quit_`、`RunInLoop`/`QueueInLoop`、`mutex`。
- **读什么**：`Loop()`（epoll_wait + 分发）、`QueueInLoop`（跨线程投递）。
- **面试点**：
  - `eventfd` 的作用？（唤醒阻塞在 `epoll_wait` 的线程，用于跨线程投递任务）
  - `RunInLoop` vs `QueueInLoop`？（同线程直接执行 vs 总是入队）
  - `DoPendingFunctors` 为什么先 `swap` 再执行？（缩短临界区，避免回调里再入队造成死锁）

### 2.5 `net/EventLoopThread(Pool)` — 从 Reactor ⭐
- **关键语法**：`std::thread`、`condition_variable`（等待 loop 就绪）、`unique_ptr`。
- **面试点**（**易错**）：`EventLoop` 为什么必须在**运行它的线程内**构造？（`thread_id_` 记录构造线程，否则 `RunInLoop` 判断错，行为异常）

### 2.6 `net/TcpServer` — 服务器主体 ⭐⭐
- **关键语法**：`shared_ptr`（连接生命周期）、`deque`（发送队列）、`move`、lambda 捕获、`sendfile`。
- **读什么**：`OnAccept`（ET 循环 accept）、`OnMessage`（读+解析）、`EnqueueResponse`/`Flush`（发送队列 + 背压）、`ScheduleClose`（延迟关闭）。
- **面试点**（**最高频**）：
  - 主从 Reactor 怎么分工？（主 loop 只 accept，从 loop 处理已连接）
  - 为什么 `OnClose` 要"延迟到本轮事件结束后"执行？（避免在回调栈上释放对象 → UAF）
  - `sendfile` 解决了什么？（零拷贝，数据不经用户态）
  - 发送队列 + `EPOLLOUT` 如何实现"背压"？（EAGAIN 时保留进度，注册可写事件续传）

## 第 3 阶段：HTTP 层

### 3.1 `http/HttpRequest/HttpResponse`
- **关键语法**：`std::optional`、`unordered_map`、`vector`、静态工厂函数。
- **面试点**：`HttpResponse` 为什么区分 `kString/kFile/kMultipart`？（决定走内存拷贝还是 sendfile）

### 3.2 `http/HttpParser` — 状态机解析 ⭐⭐
- **关键语法**：`enum class`（状态）、`string_view`、`from_chars`、`optional`。
- **读什么**：`Parse` 状态机、`FinishRequest`、`ParseMultipartBoundary`。
- **面试点**（**高频**）：
  - 怎么处理**粘包/半包**？（状态机 + Buffer 保留未完成数据）
  - 中间状态为什么保存在 parser 里（`partial_`）而不是调用者的 `out`？（跨多次 `recv` 调用，`out` 每次是新的 → 会丢 method/path；**这是实测踩到的真实 bug**）
  - keep-alive 怎么支持？（`FinishRequest` 里复位 `state_`）

## 第 4 阶段：业务层

### 4.1 `api/Router` — 路由
- **关键语法**：`std::function` 存 handler、lambda、通配符匹配（`:uid`）。
- **面试点**：路由表为什么用 `vector` 线性匹配而不是 map？（路由少、支持通配符，简单够用）

### 4.2 `dicom/DicomFile`
- **关键语法**：`optional`、条件编译（`#if defined(DWS_HAVE_DCMTK)`）。
- **面试点**：为什么用条件编译？（未装 DCMTK 时可退化为 stub，先跑通网络层）

### 4.3 `store/MetadataDao` — 元数据库 ⭐
- **关键语法**：RAII、`optional`、`thread_local`（每线程只读连接）、前置声明。
- **读什么**：`Init`（建表 + WAL）、`ReadConn`（每线程只读连接）。
- **面试点**：
  - WAL 模式的好处？（读写并发 + 断电一致性）
  - 为什么每线程一个只读连接？（实测：多 worker 争抢单连接会把吞吐拖垮）
  - 复合索引 `(patient_id, study_date, modality)` 怎么服务 QIDO？（最左前缀）

### 4.4 `store/ObjectStore` — 对象存储
- **关键语法**：文件 IO、`rename` 原子性、`atomic` 序号。
- **面试点**：为什么"先写 `.tmp` 再 `rename`"？（原子可见：要么完整，要么不存在）

## 第 5 阶段：整体架构与数据流

- `src/main.cpp`：如何把各模块**组装**起来（命令行 → 存储 → 路由 → 服务器 → 事件循环）。
- **一个请求的完整生命周期**（务必能口述）：
  ```
  accept → Channel 读事件 → OnMessage 读入 Buffer → HttpParser 解析
    → SubmitRequest 交线程池 → worker 执行 Router::Dispatch
      → MetadataDao 查询 / ObjectStore 读文件
    → QueueInLoop 回 IO 线程 → EnqueueResponse 入发送队列
      → Flush write/sendfile → 响应发出
  ```
- **面试点**：为什么 IO 线程不做业务？（业务可能阻塞，会卡住事件循环）

## 第 6 阶段：面试高频问题（按模块归类的自测清单）

1. **并发模型**：为什么用"主从 Reactor + 线程池"？各自职责？
2. **ET/LT**：区别、为什么 ET 要循环读写到 `EAGAIN`？
3. **无锁队列**：MPSC 为什么不是 MPMC？内存序怎么配？
4. **零拷贝**：`sendfile` 原理，相比 `read+write` 省了什么？
5. **HTTP 解析**：粘包/半包、状态机、keep-alive。
6. **生命周期**：连接对象何时销毁？为什么延迟关闭？
7. **数据库**：WAL、索引、并发读瓶颈（**有实测数据**）。
8. **性能**：TTFB 1.4ms、吞吐 2.6GB/s、QIDO 1264 QPS 是怎么测的、瓶颈在哪。
9. **踩坑**：讲出你修过的真实 bug（本文件第 1、3、4 阶段里标注的"实测 bug"）。
