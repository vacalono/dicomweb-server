# 在云端 Linux 上从零运行 dicomweb-server

> 本文记录在一台**全新 Ubuntu 云主机**上把本项目跑起来的完整步骤，所有命令均已实测。
> 实测环境：Ubuntu 22.04（内核 5.15.0-78-generic）、g++ 11.3.0、CMake 3.22.1、SQLite 3.37.2、DCMTK 3.6.6。

## 0. 准备

- 云主机：Ubuntu 20.04 / 22.04（x86_64），1 核 2G 即可跑通
- 拿到 SSH 连接信息：`host`、`port`、`user`（通常 `root`）、密码或私钥
- 本机需有 `ssh` / `scp`（Windows 10+ 自带 OpenSSH）

## 1. 连接主机

```bash
ssh -p <port> root@<host>
```

首次连接会询问主机指纹，输入 `yes`。

## 2. 安装系统依赖

```bash
apt-get update
apt-get install -y build-essential cmake libsqlite3-dev libgtest-dev
# 可选：真实 DICOM 标签解析（不装则 DicomFile 退化为 stub，网络层仍可跑通）
apt-get install -y libdcmtk-dev
```

实测：`cmake version 3.22.1`、`g++ (Ubuntu 11.3.0)`。

## 3. 获取代码

**方式 A — 从本地上传**（当前项目未建 git 仓库时）：

```powershell
# 在本机 PowerShell 执行（注意 scp 用大写 -P 指定端口）
scp -P <port> -r "c:\path\to\dicomweb-server" root@<host>:/root/dicomweb-server
```

**方式 B — git clone**（若已推送到远程仓库）：

```bash
git clone <repo-url> dicomweb-server && cd dicomweb-server
```

## 4. 编译

```bash
cd dicomweb-server
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

实测配置输出：

```
SQLite3: 3.37.2
DCMTK: 3.6.6
dicomweb-server 0.1.0  |  C++17  |  Release
```

产物：`build/dicomweb-server`（约 4.7 MB）、`build/tests/dws_tests`（约 5.4 MB）。

常用开关：

| 开关 | 作用 |
|---|---|
| `-DDWS_HAVE_DCMTK=OFF` | 不编译 DICOM 编解码（未装 DCMTK 时用） |
| `-DDWS_BUILD_TESTS=OFF` | 跳过单测 |
| `-DCMAKE_BUILD_TYPE=Debug` | 调试构建（配 ASan/gdb） |

## 5. 单元测试

```bash
ctest --test-dir build --output-on-failure
```

实测：`100% tests passed, 0 tests failed out of 12`。

## 6. 运行

```bash
./build/dicomweb-server --port 8080 --data ./data
```

实测启动日志：

```
dicomweb-server starting (data=./data, db=./data/meta.db)
MetadataDao ready: ./data/meta.db (WAL)
listening on 0.0.0.0:8080 (sub reactors=0)
ready. try: curl -s http://127.0.0.1:8080/studies
```

> ⚠️ 默认 `--workers` = CPU 核数（如 96）。但 SQLite 密集的查询负载下 **worker 越多反而越慢**，
> **建议显式指定较小值**，例如 `--workers 4`。

常用参数：

```bash
./build/dicomweb-server \
  --port 8080 \
  --data ./data \
  --io-threads 4 \      # 从 Reactor 数（0=单 Reactor）
  --workers 4           # 业务线程池大小（0=IO 线程同步处理）
```

## 7. 验证

```bash
# 1) 空库应返回 []
curl -s http://127.0.0.1:8080/studies

# 2) 端到端：STOW 上传 -> QIDO 检索 -> WADO 下载（含 Range）
python3 scripts/e2e_client.py http://127.0.0.1:8080
```

实测：STOW/QIDO/WADO 全部 200、上传下载字节一致、Range 返回 `206`。

## 8. 后台运行

```bash
cd /root/dicomweb-server
nohup ./build/dicomweb-server --port 8080 --data ./data > server.log 2>&1 &
tail -f server.log
# 停止
pkill -x dicomweb-server
```

## 9. 外部访问（云平台端口映射）

- **GPU/容器云（AutoDL / SeetaCloud 等）**：通常**不开放任意端口**，只预留固定的 `6006` / `6008`。
  让服务监听这些端口即可：

  ```bash
  ./build/dicomweb-server --port 6006 --data ./data
  ```
  再到控制台查看映射出的公网地址（形如 `https://xxx.seetacloud.com:8443/`）。

- **普通云服务器（阿里云 / 腾讯云 / AWS）**：在安全组放行端口后，直接访问 `http://<公网IP>:8080/`。

## 常见问题

| 现象 | 原因 / 解决 |
|---|---|
| `cmake: command not found` | 未装：`apt-get install -y cmake` |
| 链接报 `undefined reference to DcmFileFormat...` | 装了 DCMTK 却关掉了，或反之：确认 `libdcmtk-dev` 已装并用默认 `-DDWS_HAVE_DCMTK=ON` |
| `bind(:8080) failed: Address already in use` | 端口被占：换 `--port` 或 `pkill -x dicomweb-server` |
| `sqlite3_open(...) failed: unable to open database file` | `--data` 路径不可写；程序会自动建目录，确保父路径可写 |
| 外部浏览器访问不了 | 云平台未做端口映射 / 安全组未放行（见第 9 节） |
| 压测 QPS 偏低 | SQLite 并发读瓶颈，减少 `--workers` |
| `pkill -f "./server"` 把自己也杀了 | 用 `pkill -x <精确进程名>`，避免 `-f` 匹配到命令行自身 |
